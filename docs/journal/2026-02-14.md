- Each store with an `init` function registers a `reset()` that restores `baseState` and clears `hasInitialized`
- Configuration stores without `init` (like `databaseStore`) are intentionally excluded from the reset registry
- `clearAllRepositoryCaches()` now calls `resetAllJestorStores()` before clearing TinyBase stores

**Technical Info Consulted:**
- `jestor.ts` `createStore` internals, `hasInitialized` guard, `runInit()`
- `createEntityStore.ts` — entity stores with `autoLoad: true` have an `init` hook
- `databaseStore.ts` — no `init` hook, must not be reset

**Assumptions Made:**
- Stores without an `init` function are configuration stores that should not be reset between tests
- Resetting before `destroyAllTinyBaseStores` is safe because no React components are mounted during `beforeEach`

**Other Notes:**
