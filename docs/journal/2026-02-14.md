### 07:05 - Fix CI test failures caused by stale Jestor store state across test files [Claude Sonnet 4.5 claude-sonnet-4-5-20250929]

**User Prompt:**
CI test failure: ClassOverview unable to find "Mathe" after rendering

**Issues Encountered:**
- With `isolate: false` in Vitest, Jestor store module-level singletons persist across test files
- The `hasInitialized` guard in `jestor.ts` prevents data-loading stores from triggering `init` (i.e. `loadAll`) after `clearAllRepositoryCaches()` resets the TinyBase/IndexedDB layer
- Tests that run after other tests that used the same store would see stale (empty) entities
- Naive "reset all stores" approach reset `databaseStore` too, wiping out `setDatabaseMode('example')` mid-test and breaking `exampleDatabaseSeed.test.ts`

**Decisions Made:**
- Added a global `jestorStoreResetters` registry in `jestor.ts` (mirroring `repositoryCacheClearers` in `createRepository.ts`)
- Each store with an `init` function registers a `reset()` that restores `baseState` and clears `hasInitialized`
- Configuration stores without `init` (like `databaseStore`) are intentionally excluded from the reset registry
- `clearAllRepositoryCaches()` now calls `resetAllJestorStores()` before clearing TinyBase stores

**Technical Info Consulted:**
- `jestor.ts` `createStore` internals, `hasInitialized` guard, `runInit()`
- `createEntityStore.ts` — entity stores with `autoLoad: true` have an `init` hook
- `databaseStore.ts` — no `init` hook, must not be reset

**Assumptions Made:**
- Stores without an `init` function are configuration stores that should not be reset between tests
- Resetting before `destroyAllTinyBaseStores` is safe because no React components are mounted during `beforeEach`
