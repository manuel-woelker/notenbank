### 07:32 - Fix IndexedDB blocked on Tabula Rasa database deletion

**User Prompt:**
Help me debug the following issue: When deleting the database via tabula rasa, it is blocked on indexeddb. One theory that React calls the resetExampleDatabase function twice simultaneously.

**Issues Encountered:**
- `indexedDB.deleteDatabase()` was firing the `onblocked` event and never completing
- The previous `onblocked` handler silently resolved the promise early, meaning the code continued before the database was actually deleted — causing writes into a stale, still-open connection

**Decisions Made:**
- Added `db.onversionchange = () => db.close()` in `IndexedDBRepository.initDB()`. This is the standard IndexedDB pattern: when a delete (or version upgrade) is requested, all open connections receive a `versionchange` event and should close themselves to unblock the operation.
- Changed the `onblocked` handler in `resetExampleDatabase()` to log a warning and keep the promise pending (instead of resolving early), so the code only continues after `onsuccess` fires — i.e., after the database is truly gone.
- The React double-call theory was investigated and ruled out: `handleExampleReset` is a button click handler (not a `useEffect`), so React StrictMode double-invocation does not apply. The `dbSwitching` guard also prevents double-clicks.

**Technical Info Consulted:**
- MDN IndexedDB: `IDBDatabase.onversionchange` — connections must close when they receive this event to allow pending deletes/upgrades to proceed.

**Assumptions Made:**
- All repositories connect through `IndexedDBRepository.initDB()`, so adding the handler there covers all open connections uniformly.

**Other Notes:**
- All 214 tests pass after the fix.

### 17:30 - Replace IndexedDBRepository with RxDB

**User Prompt:**
Replace the hand-rolled IndexedDBRepository (~470 lines) with an RxDBRepository class that uses the RxDB library over IndexedDB (via Dexie storage adapter), keeping the same Repository<T, TCreate> interface.

**Issues Encountered:**
- RxDB v16 TypeScript types only allow `additionalProperties: false` in JSON schemas, but we need `true` since Zod handles validation — worked around with type assertion `true as unknown as false`
- RxDB's Dexie storage requires all indexed fields to be in the schema's `required` array (DXE1 error)
- Schema mismatch errors (DB6) in tests when the same database/collection name was used with different schemas across test suites — fixed by making all test configs use consistent schemas
- Data leaking between tests because `db.close()` preserves data and Dexie's internal caches survive IDBFactory replacement — fixed by using `db.remove()` (which deletes all data) in `destroyAllRxDatabases()`

**Decisions Made:**
- Created `RxDBRepository.ts` implementing the existing `Repository` interface via RxDB's `createRxDatabase` and `addCollections` APIs
- Module-level `databaseCache` (Map<string, Promise<RxDatabase>>) prevents duplicate database creation across repositories sharing the same database
- RxDB JSON Schema is permissive (`additionalProperties: true`) — we rely on Zod for data validation, not RxDB's schema
- Generic Date serialization: all Date fields are converted to ISO strings on write and back to Date on read (not just createdAt/updatedAt), handling entities like Assessment with a `date` field
- `inTransaction` becomes a no-op shim since RxDB manages transactions internally
- `ensureNotenbankStores` becomes a no-op since RxDB manages collections lazily via `db.addCollections()`
- `clearAllRepositoryCaches()` is now async — it must `await destroyAllRxDatabases()` before clearing repository instance maps
- Created a global `testSetup.ts` (via Vitest setupFiles) that resets IDBFactory and clears all caches before each test
- Kept `IndexedDBRepository.ts` and its tests for reference, just no longer wired up

**Technical Info Consulted:**
- RxDB v16 documentation: `createRxDatabase`, `addCollections`, `RxJsonSchema`, `bulkInsert`, `doc.patch()`, `db.remove()`, `removeRxDatabase`
- RxDB uses Dexie internally for the `getRxStorageDexie()` adapter
- `fake-indexeddb` provides the in-memory IndexedDB implementation for tests

**Assumptions Made:**
- RxDB doesn't enforce uniqueness on compound indexes (the assessmentGrades `['assessmentId', 'studentId']` unique constraint) — application logic already prevents duplicates
- The `onUpgrade` callback in repository configs is unused by RxDB but kept for API compatibility

**Other Notes:**
- All 214 tests pass after the change
- `pnpm run check` (typecheck + prettier + eslint + tests) passes
- `pnpm build` succeeds
- Files changed: created `RxDBRepository.ts`, modified `createRepository.ts`, `notenbankDb.ts`, `exampleDatabaseSeed.ts`, `testSetup.ts`, `vite.config.ts`, `createRepository.test.ts`, and ~20 test files (replaced IDBFactory setup with clearAllRepositoryCaches)
