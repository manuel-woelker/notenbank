### 16:21 - Add separate GitHub Action for E2E tests

**User Prompt:**
setup a separate github action for running the e2e tests

**Issues Encountered:**
- Initial workflow didn't start the dev server before running E2E tests
- Tests would fail because the application at http://localhost:5173 wasn't available

**Decisions Made:**
- Created a separate workflow file `.github/workflows/ui-e2e.yml` to keep E2E tests independent from the main CI workflow
- Used the same trigger patterns as `ui-ci.yml` to ensure consistency
- Installed only Chromium browser to reduce setup time and resource usage (sufficient for the test suite)
- Added artifact upload for both `playwright-report/` and `test-results/` directories for debugging failed tests
- Set artifact retention to 30 days to match the existing CI workflow
- Configured Playwright's `webServer` option to automatically start the dev server before tests
- Removed the build step from the workflow since webServer handles server startup
- Set `reuseExistingServer: !process.env.CI` to reuse local dev server during development
- Set timeout to 120 seconds to allow server startup time in CI environment

**Technical Info Consulted:**
- Existing `.github/workflows/ui-ci.yml` for workflow structure and conventions
- `ui/playwright.config.ts` to understand Playwright configuration and test directory location
- `ui/package.json` to verify the `test:e2e` script command
- Playwright GitHub Action documentation patterns for browser installation
- Playwright webServer documentation for automatic server management

**Assumptions Made:**
- E2E tests are located in `ui/e2e/` directory as configured in `playwright.config.ts`
- The dev server (`pnpm dev`) on port 5173 is required for E2E tests
- Chromium browser is sufficient for running all E2E tests (based on no evidence of cross-browser testing requirements)
- Artifacts from `playwright-report/` and `test-results/` are sufficient for debugging
- 120 second timeout is sufficient for the dev server to start in CI

**Other Notes:**
- The workflow uses `ubuntu-latest` runner for consistency with the existing CI workflow
- The workflow only triggers on changes to `ui/**` path and the workflow file itself, avoiding unnecessary runs
- `continue-on-error: false` ensures the workflow fails if E2E tests fail
- Using Playwright's built-in webServer is cleaner than external packages like `start-server-and-test`
